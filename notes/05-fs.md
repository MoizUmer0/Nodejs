# 1. What is the File System Module?

Node.js provides a built-in module called:

```text
fs
```

`fs` stands for **File System**.

The `fs` module allows Node.js applications to interact with files and directories.

### Using `fs`, we can:

* Create files
* Read files
* Write files
* Append data
* Copy files
* Delete files
* Check file information
* Create directories
* Work with directories

---

# 2. Importing `fs`

Since `fs` is a built-in Node.js module, we don't use `./` when importing it.

```js
const fs = require("fs");
```

### Built-in module

```js
const fs = require("fs");
```

### Local module

```js
const math = require("./math");
```

The difference is:

```text
Built-in Module
      ↓
require("fs")

Local Module
      ↓
require("./math")
```

# 3. Writing to a File

The `fs` module provides two commonly used functions for writing files:

```js
fs.writeFile()
fs.writeFileSync()
```

| Function          | Type         |
| ----------------- | ------------ |
| `writeFile()`     | Asynchronous |
| `writeFileSync()` | Synchronous  |

---

## `writeFileSync()`

`writeFileSync()` writes data to a file synchronously.

```js
const fs = require("fs");

fs.writeFileSync("./test.txt", "Hello");
```

This creates:

```text
test.txt
```

with:

```text
Hello
```

### ⚠️ Important

If the file already contains data, `writeFileSync()` replaces the existing content.

For example:

```js
fs.writeFileSync("./test.txt", "Hello World");
```

The previous content will be replaced with:

```text
Hello World
```

### Flow

```text
writeFileSync()
      ↓
    WAIT
      ↓
File operation completes
      ↓
Continue execution
```

---

## `writeFile()`

`writeFile()` performs the operation asynchronously.

```js
const fs = require("fs");

fs.writeFile("./test.txt", "Hello World", (err) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log("File written successfully");
});
```

The asynchronous version uses a **callback**.

The callback handles the result after the operation completes.

# 4. Reading a File

The `fs` module provides:

```js
fs.readFile()
fs.readFileSync()
```

---

## `readFileSync()`

`readFileSync()` reads a file synchronously and returns the result.

```js
const fs = require("fs");

const result = fs.readFileSync("./contacts.txt", "utf-8");

console.log(result);
```

If `contacts.txt` contains:

```text
Piyush - 9111
John - 2222
```

The result will contain the file data.

### Flow

```text
File
 ↓
readFileSync()
 ↓
Result
```

---

## File Encoding

When reading a text file, we can specify an encoding:

```js
"utf-8"
```

Example:

```js
const result = fs.readFileSync("./contacts.txt", "utf-8");
```

The encoding tells Node.js how the file's data should be decoded into text.

---

## `readFile()`

`readFile()` reads a file asynchronously.

```js
const fs = require("fs");

fs.readFile("./contacts.txt", "utf-8", (err, result) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log(result);
});
```

The callback receives:

```text
callback(error, result)
```

### Error

If something goes wrong:

```js
if (err) {
    console.log(err);
}
```

### Result

If the operation succeeds:

```js
console.log(result);
```

### Flow

```text
File
 ↓
readFile()
 ↓
Callback
 ↓
Error / Result
```

# 5. Appending Data

Sometimes we don't want to overwrite existing content.

Instead, we want to add new data to the end of the file.

For this, we can use:

```js
fs.appendFile()
fs.appendFileSync()
```

---

## `appendFile()`

Asynchronous version:

```js
const fs = require("fs");

fs.appendFile("./test.txt", "New Data\n", (err) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log("Data appended");
});
```

The new data is added to the existing content.

---

## `appendFileSync()`

Synchronous version:

```js
const fs = require("fs");

fs.appendFileSync("./test.txt", "New Data\n");
```

Unlike `writeFileSync()`, this does **not** replace the existing content.

```text
Existing Data
      +
New Data
      ↓
Updated File
```

---

# 6. File Logging

Appending data is especially useful for creating **log files**.

A server can store information about incoming requests such as:

```text
Time
IP Address
Requested Resource
```

Example log:

```text
12:30 - 192.168.1.10 - /home
12:35 - 192.168.1.20 - /movies
12:40 - 192.168.1.15 - /about
```

Each new request can be appended to the log.

### Useful for:

* Monitoring
* Debugging
* Tracking requests
* Server logs

---

## Date and Time in Logs

JavaScript provides:

```js
new Date()
```

to get the current date and time.

Example:

```js
const fs = require("fs");

fs.appendFileSync(
    "./log.txt",
    `${new Date()} - New Request\n`
);
```

Every time this code runs, a new log entry is added.

Example:

```text
Fri Aug 14 2026 18:20:00 GMT+0500 - New Request
Fri Aug 14 2026 18:22:10 GMT+0500 - New Request
Fri Aug 14 2026 18:25:30 GMT+0500 - New Request
```

# 9. File Information with `stat`

The `fs` module provides:

```js
fs.stat()
fs.statSync()
```

These functions provide information about a file or directory.

---

## `statSync()`

```js
const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats);
```

The returned information can include:

* File size
* Creation time
* Modification time
* File information
* Whether the path is a file
* Whether the path is a directory

---

## Check Whether a Path is a File

Use:

```js
stats.isFile()
```

Example:

```js
const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats.isFile());
```

Output:

```text
true
```

---

## Check Whether a Path is a Directory

Use:

```js
stats.isDirectory()
```

Example:

```js
const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats.isDirectory());
```

If the path points to a file:

```text
false
```

# 10. Creating Directories

The `fs` module can also create directories.

Use:

```js
fs.mkdir()
fs.mkdirSync()
```

---

## `mkdir()`

Asynchronous example:

```js
const fs = require("fs");

fs.mkdir("./mydocs", (err) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log("Directory created");
});
```

This creates:

```text
mydocs/
```

---

## `mkdirSync()`

Synchronous version:

```js
const fs = require("fs");

fs.mkdirSync("./mydocs");
```

---

## Creating Nested Directories

We can create multiple directories using:

```js
{ recursive: true }
```

Example:

```js
const fs = require("fs");

fs.mkdir("./mydocs/a/b", { recursive: true }, (err) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log("Directories created");
});
```

This can create:

```text
mydocs/
└── a/
    └── b/
```

### `recursive: true`

The `recursive` option allows Node.js to create the required parent directories.

```text
mkdir("./mydocs/a/b")
          +
recursive: true
          ↓
Creates mydocs
      ↓
Creates a
      ↓
Creates b
```

# 12. Async vs Sync

Many `fs` operations have two versions.

```text
Asynchronous                 Synchronous
     │                            │
     ↓                            ↓
writeFile()              writeFileSync()
readFile()               readFileSync()
appendFile()             appendFileSync()
copyFile()               copyFileSync()
unlink()                 unlinkSync()
stat()                   statSync()
mkdir()                  mkdirSync()
```

### Naming Pattern

Generally:

```text
Function
   +
Sync
   ↓
Synchronous Version
```

Example:

```js
fs.readFile()
```

becomes:

```js
fs.readFileSync()
```

The `Sync` version performs the operation synchronously.

The version without `Sync` is generally asynchronous.

# 13. Blocking vs Non-Blocking

Understanding synchronous and asynchronous operations is important in Node.js.

## Synchronous

Synchronous operations can block execution until the operation finishes.

```text
Task 1
  ↓
 WAIT
  ↓
Task 1 Complete
  ↓
Task 2
```

Example:

```js
const data = fs.readFileSync("./file.txt", "utf-8");

console.log(data);

console.log("Next Task");
```

---

## Asynchronous

Asynchronous operations allow Node.js to continue execution while the operation is being handled.

```text
Task 1 ─────────────────→ Result
  │
  └──→ Continue Other Work
```

Example:

```js
fs.readFile("./file.txt", "utf-8", (err, data) => {
    console.log(data);
});

console.log("Next Task");
```

Simplified execution:

```text
readFile()
   ↓
Continue execution
   ↓
"Next Task"
   ↓
File operation completes
   ↓
Callback executes
```

---

# 14. Why Asynchronous Operations Matter

Node.js applications commonly handle many requests.

Imagine a server receiving:

```text
Request 1
Request 2
Request 3
Request 4
Request 5
```

If every operation blocks the main JavaScript execution:

```text
Request 1
   ↓
Blocking Operation
   ↓
WAIT
   ↓
Request 2
   ↓
Blocking Operation
   ↓
WAIT
```

This can increase response time and reduce the server's ability to handle concurrent work efficiently.

With asynchronous operations:

```text
Request 1 ───────────────→ Result
   │
   ├──→ Request 2
   │
   ├──→ Request 3
   │
   ├──→ Request 4
   │
   └──→ Request 5
```

Node.js can continue executing other JavaScript work while an asynchronous I/O operation is pending.

### Important concepts to understand

* Synchronous execution
* Asynchronous execution
* Blocking operations
* Non-blocking operations
* Event Loop
* Threads
* Node.js architecture
