# Node.js — File System (fs) Module

## What is File System (fs)?

Node.js provides a built-in module called:

```js
fs

fs stands for File System.

The fs module allows Node.js applications to interact with files and directories.

Using the fs module, we can:

Create files
Read files
Write to files
Append data to files
Copy files
Delete files
Check file information
Create directories
Work with directories
Importing the fs Module

Since fs is a built-in Node.js module, it does not require ./.

const fs = require("fs");

Unlike a local module:

const math = require("./math");

we simply use:

require("fs");

because fs is already provided by Node.js.

Writing to a File

The fs module provides two commonly used functions for writing files:

fs.writeFile()

and:

fs.writeFileSync()

The main difference is that:

writeFileSync() is synchronous
writeFile() is asynchronous
writeFileSync()

writeFileSync() writes data to a file synchronously.

Example:

const fs = require("fs");

fs.writeFileSync("./test.txt", "Hello");

This creates:

test.txt

with:

Hello
Important

If the file already contains data, writeFileSync() will overwrite the existing content.

For example:

fs.writeFileSync("./test.txt", "Hello World");

The previous content will be replaced with:

Hello World
writeFile()

writeFile() performs the file-writing operation asynchronously.

Example:

const fs = require("fs");

fs.writeFile("./test.txt", "Hello World", (err) => {
    if (err) {
        console.log(err);
    }
});

The asynchronous version uses a callback function.

The callback can be used to handle errors after the operation completes.

Synchronous vs Asynchronous

There are two important concepts when working with Node.js file operations:

Synchronous

The operation runs synchronously and blocks execution until the operation is completed.

Example:

fs.writeFileSync();
Asynchronous

The operation runs asynchronously and uses a callback to handle the result.

Example:

fs.writeFile();

A simplified idea:

Synchronous

Task
 ↓
Wait for task to finish
 ↓
Continue execution
Asynchronous

Task
 ↓
Start task
 ↓
Continue execution
 ↓
Callback receives result

The deeper concepts of:

Blocking
Non-blocking
Event Loop
Threads
Node.js architecture

are important for understanding why asynchronous operations are commonly preferred in server applications.

Reading a File

The fs module can also be used to read files.

There are two common functions:

fs.readFile()

and:

fs.readFileSync()
readFileSync()

readFileSync() reads a file synchronously and returns the result.

Example:

const fs = require("fs");

const result = fs.readFileSync("./contacts.txt", "utf-8");

console.log(result);

If contacts.txt contains:

Piyush - 9111
John - 2222

the result will contain the file data.

File Encoding

When reading a text file, we can specify an encoding:

"utf-8"

Example:

const result = fs.readFileSync("./contacts.txt", "utf-8");

The encoding tells Node.js how the file data should be decoded into text.

readFile()

readFile() reads a file asynchronously.

Example:

const fs = require("fs");

fs.readFile("./contacts.txt", "utf-8", (err, result) => {
    if (err) {
        console.log(err);
    } else {
        console.log(result);
    }
});

The callback receives two important values:

callback(error, result)
Error

If something goes wrong:

if (err) {
    console.log(err);
}
Result

If the operation succeeds:

console.log(result);
Difference Between readFile() and readFileSync()
readFileSync()
const result = fs.readFileSync("./contacts.txt", "utf-8");

console.log(result);

The result is directly returned.

File
 ↓
readFileSync()
 ↓
Result
readFile()
fs.readFile("./contacts.txt", "utf-8", (err, result) => {
    console.log(result);
});

The result is provided through a callback.

File
 ↓
readFile()
 ↓
Callback
 ↓
Error / Result
Appending Data to a File

Sometimes we don't want to overwrite the existing content.

Instead, we want to add new content at the end of the file.

For this, we can use:

fs.appendFile()

or:

fs.appendFileSync()
appendFile()

Example:

const fs = require("fs");

fs.appendFile("./test.txt", "New Data\n", (err) => {
    if (err) {
        console.log(err);
    }
});

The new content is added to the existing file.

appendFileSync()

Example:

const fs = require("fs");

fs.appendFileSync("./test.txt", "New Data\n");

Instead of replacing the existing content, the new data is added at the end.

Why appendFile() is Useful

Appending is useful when creating log files.

For example, a server can store information about incoming requests:

Time
IP Address
Requested Resource

A log file could look like:

12:30 - 192.168.1.10 - /home
12:35 - 192.168.1.20 - /movies
12:40 - 192.168.1.15 - /about

Each new request can be appended to the log.

This is useful for:

Monitoring
Debugging
Tracking requests
Server logs
Date and Time in Logs

JavaScript provides:

new Date()

to get the current date and time.

Example:

fs.appendFileSync(
    "./log.txt",
    `${new Date()} - New Request\n`
);

Every time the operation runs, a new entry can be added to the log file.

Copying Files

The fs module can also copy files.

One function available for this is:

fs.copyFile()

There is also:

fs.copyFileSync()

Example:

const fs = require("fs");

fs.copyFileSync("./test.txt", "./copy.txt");

This creates a copy of:

test.txt

as:

copy.txt
Deleting Files

Node.js allows us to delete files using:

fs.unlink()

or:

fs.unlinkSync()

Example:

const fs = require("fs");

fs.unlink("./copy.txt", (err) => {
    if (err) {
        console.log(err);
    }
});

The specified file will be deleted.

Checking File Information

The fs module provides:

fs.stat()

and:

fs.statSync()

These functions allow us to get information about a file or directory.

Example:

const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats);

The returned information can include:

File size
Creation time
Modification time
File information
Whether the path is a file
Whether the path is a directory
Checking Whether a Path is a File

We can use:

stats.isFile()

Example:

const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats.isFile());

Output:

true
Checking Whether a Path is a Directory

We can use:

stats.isDirectory()

Example:

const fs = require("fs");

const stats = fs.statSync("./test.txt");

console.log(stats.isDirectory());

If the path points to a file, the result will be:

false
Creating Directories

The fs module can also create directories.

We can use:

fs.mkdir()

or:

fs.mkdirSync()

Example:

const fs = require("fs");

fs.mkdir("./mydocs", (err) => {
    if (err) {
        console.log(err);
    }
});

This creates:

mydocs/
Creating Nested Directories

We can create multiple directories using the recursive option.

Example:

fs.mkdir("./mydocs/a/b", { recursive: true }, (err) => {
    if (err) {
        console.log(err);
    }
});

This can create:

mydocs
└── a
    └── b

The recursive: true option allows Node.js to create the required parent directories as well.

Async and Sync Naming Pattern

Many fs operations have two versions.

Asynchronous                 Synchronous
     │                            │
writeFile()              writeFileSync()
readFile()               readFileSync()
appendFile()             appendFileSync()
copyFile()               copyFileSync()
unlink()                 unlinkSync()
stat()                   statSync()
mkdir()                  mkdirSync()

The Sync version performs the operation synchronously.

The version without Sync generally performs the operation asynchronously.

Blocking and Non-Blocking Operations

Understanding synchronous and asynchronous operations is important in Node.js.

Synchronous Operations

Synchronous operations can block execution until the operation finishes.

Task 1
  ↓
Wait
  ↓
Task 2
Asynchronous Operations

Asynchronous operations allow Node.js to continue execution while the operation is being handled.

Task 1 ────────────────→ Result
  │
  └──→ Continue other work

This is especially important when building backend applications and web servers.

Why Asynchronous Operations Matter

Node.js applications commonly handle many requests.

Imagine a server receiving:

Request 1
Request 2
Request 3
Request 4
Request 5

If every operation blocks the main execution, the server can become slow.

Asynchronous operations allow Node.js to handle other work while waiting for file or other I/O operations to complete.

This is why understanding:

Synchronous execution
Asynchronous execution
Blocking operations
Non-blocking operations
Event Loop
Threads

is extremely important for Node.js backend development.
